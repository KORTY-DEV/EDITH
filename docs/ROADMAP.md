# E.D.I.T.H. — Roadmap

Цель: локальный голосовой дворецкий, который по-настоящему знает хозяина (речь, манеры, привычки, дела)
и помогает по ПК. Строго локально, уживается с играми (World of Tanks, 79 fps cap).

Критерий готовности: неделя обычной работы, в течение которой EDITH используется постоянно,
и ни один модуль не пришлось запускать или чинить руками.

## Приоритеты

1. **Личность и память о хозяине** — собеседник, а не командная строка.
2. **Голос** — wake почти без ложных, свободная речь, быстрый естественный ответ.
3. **Руки** — по порядку: браузер → приложения и окна → UI Automation → файлы → документы.
4. **Зрение** — UIA + OCR, VLM только по необходимости.
5. **Система** — только отложенное выключение (по таймеру / когда завершится ИИ-агент).

Вне рамок: написание и починка кода, облачные модели, настройка системы (громкость, сеть и т.п.).

## Железо и раскладка моделей

GTX 1070 8 ГБ (Pascal, CC 6.1), Ryzen 5 3600X, 32 ГБ DDR4.

| Роль | Где | Кандидаты |
|---|---|---|
| Wake | CPU | Wake V3 (stage1 + verifier) |
| STT | CPU | GigaAM-v2 (ONNX) / faster-whisper int8 |
| TTS | CPU | Silero |
| Эмбеддинги | CPU | bge-m3 / multilingual-e5-small |
| OCR | CPU | Windows.Media.Ocr |
| Router / беседа | GPU | qwen3.5:4b |
| Worker / агент | GPU | универсальная 7–9B с хорошим tool-calling |
| Зрение | GPU | 7B VLM, грузится вместо Worker |

Правило «один GPU-слот»: в VRAM одна большая модель, остальные выгружаются. KV-кэш q8_0 + flash attention.
Выбор моделей закрепляется бенчмарком на этой машине (скорость, контекст, FPS в танках).

## Этапы

### 0. Гигиена
- Закоммитить `config/wake.json` и eval-отчёты, удалить `build-verify*`.
- `scripts/verify.ps1`: build + все тесты + smoke (сборка в scratch, т.к. запущенная EDITH лочит `bin\Release`).
- Разрезать `App.xaml.cs` на сервисы без изменения поведения.

### 1. Ядро «одна система»
- Фоновый хост: автозапуск, watchdog, health-check'и (Ollama, микрофон, модели), самовосстановление.
- Шина событий и модель задачи: Task → Step → ToolCall → Result → Report.
- Журнал действий (SQLite, append-only).
- ResourceManager: GPU-слот, загрузка/выгрузка моделей, GameGuard (VRAM/GPU через nvidia-smi),
  очередь отложенных задач («сделаю после боя»).
- UI состояния: слышит / думает / какой инструмент / ошибка + лента журнала.

### 2. Личность и память о хозяине (главный этап)
- **Профиль хозяина**: как обращаться, распорядок, игры, интересы, люди, текущие дела, предпочтения в ответах.
- **Стиль речи хозяина**: словечки, сленг, как он формулирует просьбы — чтобы понимать с полуслова.
- **Характер EDITH**: единый образ дворецкого (тон, манеры, юмор, когда краткость, когда развёрнуто),
  описанный в одном persona-файле и выдерживаемый во всех ответах; эталонные примеры реплик.
- **Эпизодическая память**: саммари каждого разговора и выполненной задачи; «что мы вчера обсуждали».
- **Хранилище**: SQLite + FTS5 + локальные эмбеддинги; релевантные воспоминания подмешиваются в каждый ответ.
- **Автоизвлечение фактов** после разговора; чувствительное — только с подтверждением; «что ты про меня знаешь» / «забудь».
- **Проактивность без навязчивости**: приветствие по времени суток и напоминания. Без расспросов вроде «как прошёл бой» (решение хозяина 25.09).
- Опционально: распознавание голоса хозяина (speaker verification) — отличать его от других и снижать ложные wake.
- Файнтюн модели на 1070 не планируется: личность держится на persona + памяти + примерах.

### 3. Голос
- STT на CPU: GigaAM-v2 или faster-whisper int8, Vosk — только fallback. Silero VAD.
  Правила разбора (`VoiceCommandText`, wake-фразы) рассчитаны на текст Vosk без пунктуации:
  перед сменой STT научить их игнорировать запятые/точки («Стой, а открой…»).
- Wake в реальных условиях: 24–72 ч записи обычного дня, метрика ложных/сутки
  (цель ≤ 1/сутки при ≥ 95% recall); ложные срабатывания автоматически → hard negatives.
- Задержка wake → первый звук < 1.5 с: стриминг LLM → TTS по предложениям.

### 4. Мозг-агент
- Нативный tool-calling Ollama вместо самописного JSON-парсера.
- Цикл: план → шаги → наблюдение → проверка, бюджет по шагам и времени, отмена голосом, промежуточные доклады.
- Детерминированные навыки делают основную работу, модель принимает маленькие решения.

### 5. Руки (в порядке приоритета)
1. Браузер (Playwright, отдельный профиль): найти, открыть, прочитать, пересказать; скачивание — с подтверждением.
2. Приложения и окна: запуск, закрытие, переключение, раскладка.
3. UI Automation (FlaUI): кнопки, поля, меню в любых программах.
4. Файлы: поиск, перемещение, разбор «Загрузок», переименование; удаление только в корзину.
5. Документы: чтение и пересказ PDF / DOCX / TXT, поиск по ним.
6. Отложенное выключение: по таймеру и по завершении работы ИИ-агента (через его Stop-hook или отслеживание процесса).

### 6. Зрение
- «Что на экране?»: UIA-дерево + OCR на CPU.
- VLM в GPU-слот только когда этого мало. Камера — только по явному включению.

### 7. Безопасность (сквозная, с этапа 1)
- Уровни: read → safe-write → destructive → external; destructive и external — всегда с подтверждением.
- Undo по умолчанию (корзина, журнал).
- Секреты — DPAPI / Windows Credential Manager вместо `secrets/*.txt`.
- Контент из веба и файлов — данные, не команды.

## Вехи

- **M1** — EDITH стартует сама, UI показывает, что она делает, есть журнал.
- **M2** — EDITH помнит хозяина и прошлые разговоры, говорит в едином характере.
- **M3** — целый день с EDITH: ≤ 1 ложного wake, свободная речь понимается.
- **M4** — браузер, окна, файлы, документы по голосу, многошаговые просьбы.
- **Готово** — неделя без ручных запусков и починок.
